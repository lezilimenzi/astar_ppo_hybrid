# Pipeline Overview: Perception → A* → PPO → PX4 Control

이 문서는 `px4_ws/src` 워크스페이스의 ROS 2 노드·토픽 흐름과, 학습 코드(`PX4-Autopilot/rl/env_2d_nav.py`, `train_ppo_2d.py`)와의 대응 관계를 정리한다. 하이브리드 내비게이션(전역 그리드 경로 + 지역 RL)을 기준으로 서술한다.

## 0. 시뮬레이션 월드: `obstacle_course_light_2x.world`

월드 파일:  
`PX4-Autopilot/Tools/simulation/gazebo-classic/sitl_gazebo-classic/worlds/obstacle_course_light_2x.world`  

원본 `obstacle_course_light` 대비 **XY만 2배**이며, **박스 높이(z)=4 m, 모델 pose z=2 m(중심)** 로 지면 위 장애물이 맞물리도록 되어 있다. 모든 장애물은 **`static` 박스**이다. Gazebo에서 `<box><size>`는 **x, y, z** 순(가로·세로·높이)이며, `<pose>`는 모델(링크) **중심** 좌표이다.

### 0.2 장애물 상세 (SDF 모델명, 중심 pose, size)

**읽는 법:** `size`는 **(dx, dy, dz)** — 지면에서 **x 길이·y 길이** 순. 끝점 구간은 박스에 대해 `[중심 − size/2, 중심 + size/2]`로 닫힌 구간(단위 **m**)이다.

- **x 방향으로 긴** 막대(`dx ≫ dy`): 길이 방향은 **x(x₁, x₂)** 로만 적고, 얇은 쪽(세로) 위치는 **y 중심** 한 값으로 적는다.
- **y 방향으로 긴** 벽·막대(`dy ≫ dx`): 길이 방향은 **y(y₁, y₂)** 로만 적고, 얇은 쪽(가로) 위치는 **x 중심** 한 값으로 적는다.

전체 3D 배치는 **중심 (x, y, z)** 열을 보면 된다.

### 0.3 Course R / L, 스폰·호밍·목표 (`goals.yaml` + `course_goal_publisher`)

설정 파일: `px4_nav_planner/config/goals.yaml` (아래 값은 2× 월드용 예시).

| 항목 | 값 (ENU, goals.yaml에 적힌 숫자) | 의미 |
|------|----------------------------------|------|
| `spawn_enu` | (1.01, 0.98, 0.83) | Gazebo/MAVROS에서 이륙 위치와 맞춘 **스폰 기준점** (주석: `sitl_run.sh` 기본) |
| `home_xyz` | (0.0, 16.0, 2.5) | **호밍 목표** — 스폰과 **같은 ENU 스케일**에서 (0, 16) 근처(윗쪽 중앙 통로)로 먼저 이동 |
| `goal_R` | (16.0, -16.4, 2.5) | **Course R** 최종 목표 — **+X ㄹ** 코스 쪽, **남서 귀퉁이 근처** (y≈-16) |
| `goal_L` | (-16.0, -16.4, 2.5) | **Course L** 최종 목표 — **−X S** 코스 쪽, **남서 귀퉁이 근처** |

**`course_goal_publisher_node`** 동작 요약:

1. 활성화 시 `home_xyz`로 호밍(위치 setpoint). 퍼블리시 pose는 **`(home_xyz - spawn_enu)`** (`odom` 프레임, 코드상 MAVROS 로컬과 정합).
2. 호밍 완료 후 `/planner/goal` 에 **한 번** 목표를 올림. 이때 pose는 **`(goal_{R|L} - spawn_enu)`** 이다. YAML의 goal은 **월드/맵과 같은 스케일**의 좌표로 두고, 노드에서 스폰 오프셋을 뺀 값이 **odom 메시지**에 실린다.

**한 줄 요약**

- **출발**: 시뮬에서 Iris는 `spawn_enu` 부근에서 시작 → 호밍으로 **대략 (0, 16)** 월드 근처로 올라간 뒤 미션 시작.  
- **Course R**: 최종 목표 **월드 (16, -16.4)** 부근(+X ㄹ, 하단 통로 쪽).  
- **Course L**: 최종 목표 **월드 (-16, -16.4)** 부근(−X S, 하단 통로 쪽).  

정확한 제어 오차·호밍 성공 여부는 `home_tolerance`, PX4 트래킹에 따른다.

## 1. System Architecture

`rl_offboard_node`는 `nav_mode=hybrid`에서 **A\*(전역) + PPO(지역)의 계층적 하이브리드 구조**를 형성한다. 입력은 `/mavros/local_position/odom`(자기 위치), `/scan`(2D LiDAR), `/local_grid`(OccupancyGrid), `/planner/goal`(최종 목표) 네 가지이며, 출력은 `/mavros/setpoint_velocity/cmd_vel_unstamped`(Twist) 한 가지다.

전역 계층은 현재 그리드 상에서 로봇 셀 → 목표 셀까지 **inflation A\***(`_astar_with_inflation`)를 수행하고, B-spline으로 부드럽게 다듬은 웨이포인트열을 `/planner/path`로 퍼블리시한다. 좁은 통로에서는 `astar_min_inflation_cells`를 자동 감소시켜 막힘을 회피한다.

지역 계층의 동작과정은 다음과 같다. 현재 위치에서 경로를 따라 `hybrid_lookahead_dist_m` 앞의 lookahead 점을 골라 **목표 상대좌표(body frame)** 로 환산한 뒤, LiDAR 64빔과 함께 `obs_dim=66`짜리 관측을 만들어 학습된 **PPO 정책(`policy_hybrid_ts.pt`)** 에 넘긴다. 정책 출력 `(v, ω)`는 `obs_norm_hybrid.json`의 스케일·클립을 거쳐 ENU 속도 setpoint로 발행된다.

안전 계층으로 emergency brake(전방 0.5 m), map boundary clamp, altitude hold가 PPO 출력 위에 오버라이드되며, OFFBOARD/ARM 전환과 사전 setpoint 송출도 노드 내부에서 자동 처리한다.
